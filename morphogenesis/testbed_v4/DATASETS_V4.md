Caveats the analyst of these runs must know (PROVISIONAL):
* **The intact flag has a natural false-positive rate.** τ_J (the first percentile of the window-minimum Jaccard over natural windows) is crossed by ordinary noise: 3 of 32 natural dishes (3,000 tu) and **all 6 damage-set twins of the κ_g 1.60 dish (seed 607, which share one noise stream, CRN) are flagged not intact from t = 26 on (mean Jaccard 0.928 < 0.9332, one component, fill complete)** although nothing was done to them; its sham arm is flagged identically (it is a bit-identical twin). Damage effects must be judged against the matched twin, never against the flag alone.
* **Tail-end light runs of every delivered amplitude are not intact** (0/36 of the tail-end below/at/above switch-set runs, 0/12 tail-end wrong-location runs, and the tail-end damage-set events; only the sham runs are intact): at the tail-end disc the damage onset lies below the switch threshold (DAMAGE.md), so even the 0.7× runs exceed it. These runs carry a state flip with a body that is not intact, by design.
* **'Wrong location' is a control only for the middle and limb-side discs** (flips 2/12 and 3/12); for the tail-end discs the "other" disc is the middle one (12/12 flip, 0/12 intact): there is no more expensive disc than the tail end, so no wrong-location control exists for it. The observable tier does not label wrong-location runs.
* Dish-merge twin/sham arms hold the two clusters 14 units apart; the merge flag is per organism.
* Switch-set runs are single noise realisations at deterministic-threshold multiples; 'below' flips 16/36 and 'at' flips 33/36 under noise (the deterministic threshold is not the noisy 50 % point).
* Observer-side analyses were NOT done (the spec stops after the deliverables).
## P2 — live environment v4 (`live/`)
Server in a separate process, JSON lines over a local socket with a one-time token (as v3, protocol 2), client library standard-library + numpy only. Changes from v3: **three seed pools** — development (seeds 5000–5399) and held-out (6000–6199), both drawn from the PRIMARY population, and a **sealed GENERALISATION pool (7000–7199)** whose dishes are drawn from the φ0 and φ0.8 variants (variant a hidden function of the seed, mixed, unlabelled); **the held-out and generalisation pools are locked until `freeze(hash)`**; per-dish parameters (κ_g, g, γ factor) and variant are sealed (never returned; `status()` lists only the development range and the names of the locked pools); budgets as v3 (per episode: time, dose, actions; per session: episodes, time, dose); **per episode the server writes a hidden ORGANISM INTACT flag (plus min Jaccard, intact series, dish, variant) to the sealed `episode.json` and to a sealed `ledger.jsonl`**; settling for a new dish seed takes ≈ 35 s (1,500 tu deterministic, cached). Session state (counters, used seeds, freeze hash) survives a restart; running episodes do not.
Tests (`live/test_live.py`, **7 pass, 160 s**): (1) the API surface exposes no internal quantity — every return value (status, reset incl. error messages for locked pools, five observation levels, act, step, end) scanned for the extended forbidden vocabulary, level payload shapes checked, repeated observation identical; (2) **live trajectories are bit-identical to an offline Experiment4 run with the same seed, dish and actions** (L, X, μ, E, ū compared with `np.array_equal`); (3) **sham = twin** (hidden logs X, C, μ, L, D, E, ū bit-identical); (4) budget accounting and enforcement; (5) the sealed ledger records the ORGANISM INTACT flag for every ended episode; (6) the sealed directory is mode 0700, hidden logs only there, client docs free of mechanism vocabulary; (7) **locks hold across restart** (held-out and generalisation pools locked after a restart, unlocked after freeze, still unlocked and not re-freezable after a second restart, hash recorded) and **the generalisation pool cannot be reset before freeze** (with or without an explicit seed), and after freeze its dishes are only φ0/φ0.8.
Limitations (PROVISIONAL): single client, single thread; the dish kind is a deterministic function of (pool, seed) — a client that could read the server's code could infer it (separate process, not a security boundary against a hostile local user); budgets are not calibrated to any control task (none was run); the generalisation pool contains only the two other φ variants, not other populations.
