# Stage 6.10 visualization notes

A third internal view — **6.10 Steering & release** — inside the existing
`Inference & Identity` → **Dynamic Interfaces** tab, alongside *6.8 Dynamic
flock* and *6.9 Translation pilot*. No new top-level navigation item: `#topNav`
still has exactly the three buttons it had before, and the Playwright pass
asserts that. The default sub-view is still 6.8.

This was a visualization pass only. No Stage 6.10 analysis was re-run, no
Stage 6.10 result file was written or modified, and no conclusion here is new.
Everything shown is either copied verbatim from a frozen result file or
regenerated by a deterministic replay that is asserted equal to one.

Generator: `stage6_10_emergence_adaptive_control/code/export_demo_data_610.py`.
Bundle: `data/stage6_10_bundle.json` (177 KB), inlined by `app/build.py` into
the `/*__STAGE610_DATA__*/` placeholder like every other bundle. `file://`
operation and the no-server setup are unchanged.

---

## 1. Which episode is shown, and why

**The exporter does not choose.** Stage 6.10's Part L already declares one, in
`run_release_clarity.py`, and records it in
`data/release__fixedk.json → clarity_trajectory`:

> **median final H among `adaptive_causal` conjunctive successes** — 4 episodes
> were eligible; the median is **seed 7**, final H = **0.882**.

Median, not maximum: the clearest example has to be typical of the successes,
not the best of them. The exporter reads `seed`, `arm`, `rule`, `n_eligible`
and `caveat` straight out of that record, asserts that the episode it exports
is exactly that seed and arm, and carries `rule` and `caveat` into the bundle
so the page displays both — the rule in the sub-header (`iiRepNote`) and again
with the caveat in **Details**. No nicer-looking episode is substituted, and
this exporter contains no selection logic of its own to substitute one with.

The turn shown is the **90° heading turn** the frozen task defines:
`h* = rotate_cw(h0)`, here ↑ → → (`ROT_CW = [3,2,0,1]`, up→right). The lattice
is fixed; nothing translates. Stage 6.9 is where translation lives, and it
failed its feasibility gate.

## 2. Data provenance, and what had to be replayed

The exporter reads **only** these four frozen files, all read-only:

| file | what is taken from it |
|---|---|
| `release__fixedk.json` | `clarity_trajectory` (seed/arm/rule/caveat), the 16 release records and `H_trace` |
| `closed_loop__fixedk.json` | the episode: `I0`, `h0`, `h*`, `k_act`, all 24 control records (`I`, `actuators`, `B_do`, `H_current`, `q_clump`, …), identity statistics, the conjunctive score, `final_z` / `final_I`, and every arm's summary |
| `controllability__main.json` | the frozen task cell (`f0.5_T24`) and the primary stratum (7 of 12 episodes) with its `claim_scope` string |
| `uncontrolled_reference__main.json` | the identity validity envelope at horizon 24 and its calibration |

**Regenerated by deterministic replay** — the per-timestep headings only.
`run_closed_loop.py` drops `z_hist` explicitly ("the full trajectory does not
fit in the result file"), so the science files contain interior sets, interface
sets and metrics but no bird headings except one final frame. The exporter
re-runs the frozen simulator at the same seed and regime, feeding it the
**recorded** action sequence, and asserts every replayed quantity against the
file it must match:

- the qualifying start `I0` at t0 must equal `closed_loop__fixedk.json`'s `I0`,
  and `h0` / `rotate_cw(h0)` must equal the recorded `h0` / `h*`;
- `H*(I_t, t+1)` from the replayed state must equal each control record's
  `H_current` to 1e-12, at all 24 steps;
- the replayed final state and lineage must equal `final_z` / `final_I`;
- the recomputed structural interface's size must equal `B_struct_size` at
  every step;
- the release replay must reproduce all 16 frozen release records
  (`H_current`, `I_size`, `q_clump`, `n_components`) and the `H_trace` exactly.

A replay that drifted fails the export loudly instead of feeding the demo a
different trajectory. The exporter is re-runnable and idempotent: every
required key is fetched through a helper that names the file and the key it
could not find, so a missing, mid-write or re-schema'd result file produces a
clear failure rather than a partial bundle. It also cross-checks the files
against each other — the frozen cell must match the closed loop's
`actuator_fraction` / `horizon`, the clarity seed must be in the primary
stratum, `clarity_trajectory.final_H` must equal the arm's `final_H_current`,
and the envelope the closed loop scored against must equal the one the
uncontrolled reference currently publishes.

**One re-derivation that is not asserted against anything**, and is labelled as
such in the page: the emergence pass. The science ran the blind detector only
at t0. To show phases 1–3 the exporter runs the *same frozen detector* on the
*same frozen trajectory* at every timestep from t = 8 (its affinity window) to
t = 60, recording the candidate count and the qualifying candidate. The t = 60
entry **is** asserted equal to the episode's frozen `I0`; the earlier steps are
presented as detector output, not as a Stage 6.10 result, and Details says so.

## 3. What the view shows

One 20×20 lattice (nn = 400) with real heading arrows on every bird, on a
single continuous timeline **t = 0 … 99**:

| t | phase | source |
|---|---|---|
| 0–59 | emergence, no control | replayed prefix + frozen detector |
| 60–83 | control on, 24 steps | replay driven by the frozen action sequence |
| 84–99 | control off, 16 free steps | release replay, asserted against Part K |

Play / step-back / step-forward / restart / slider, same controls and same
behaviour as the 6.8 view. `drawIILattice` is used unchanged, with the same
`radius: 4.1` / `arrowScale: 2.35` the 6.8 view uses for a 400-bird lattice.

**The seven story beats** are a strip of chips above the lattice, in the order
the brief specifies: *Unstructured · Emergence · Detected thing · Dynamic
interface · Target introduced · Adaptive steering · Release*. Each jumps to a
timestep **derived from the bundle's own protocol constants** (the detector
window, t0, the horizon, the release length) — none is hand-placed. Beats 3–5
are three readings of the same instant, t0, and each carries its own one-line
note in the side column; scrubbing or playing re-derives which beat is active
from t, keeping whichever of 3–5 is selected while t = t0.

**The tracked collective I_t** is the arm's own online lineage, exactly as
recorded per step. Membership change is marked the way the 6.8 view marks it:
members that *remained* stay the core blue, birds that *entered* this step are
teal, birds that *left* keep an outlined teal ring on the exterior fill, with
legend entries appearing only where a previous frame exists.

**The actuated nodes** at each step are drawn in the actuator red with the
same glow the Control view uses. These are the arm's own selection — for
`adaptive_causal`, the online sampled causal interface topped up to K = 10
under the fixed-K convention — so they are an *inferred* object, not a
reference one.

**Overlays, both OFF by default, both labelled reference rather than
inferred** and tinted with `--warn` exactly like the 6.8 view's oracle toggles:

- **Structural interface B_t (reference)** — halo ring, from the FOV rule and
  the live edge set;
- **Exact-do interface (reference)** — outer ring, computed by intervening per
  candidate.

Both are computed with full model access and were never available to the
controller; the card says so in one line. They exist only during the control
window, so both toggles are disabled outside it. Their **sizes are not even
reported** until the corresponding overlay is switched on, under a "Reference
(not inferred)" sub-heading — the blind/reference split is structural, not a
colour choice.

**Metrics beside the lattice**, and only these, varying by phase: emergence —
detected |I_t|, internal coherence, Q_clump, candidates proposed; control —
|I_t|, H*(I_t, t), actuated now, entered/left, Q_clump; release — |I_t|,
H*(I_t, t), Q_clump, components, H / H at release. Everything else is in
**Details**.

**The H\*(I_t, t) trace** puts the 24 control steps and the 16 release steps on
one axis with a divider and a shaded right half labelled *control off*, the
task threshold H ≥ 0.6 as a dotted rule, and — faint grey — the same episode's
`no_control` arm over the control window. The release half is drawn in a second
stroke so "held the turn" reads off the panel without the caption. This is what
makes *steered* versus *merely pushed* legible; Part K's finding that retention
is a property of the episode, not the arm, is stated in Details.

**Scope caption**, in the header where it cannot scroll out of view, verbatim:

> Results are scoped to the stratum where full-model control itself steers the
> collective (7 of 12 episodes); this is one illustrative episode and supports
> no aggregate claim.

## 4. What is deliberately NOT shown

- **No arm ranking.** Stage 6.10 explicitly does not establish an ordering
  among the three leading arms (`|t| ≤ 0.31`; "the heuristic's apparent lead
  over the benchmark is noise"). The view shows one arm on one episode. The
  all-arms table in Details is present because it is this episode's own data,
  and it is captioned *"n = 1: this table ranks nothing."* No arm is presented
  as a winner, and the arm selector the 6.8 control view has is deliberately
  absent here.
- **No aggregate success rate.** Part I's absolute rates are optimistic by the
  stated selection effect; only the stratum line and the per-episode numbers
  are shown.
- **No matched-budget table.** Both budget conventions were required and
  "neither table may be quoted alone"; the clarity trajectory is a fixed-K
  episode and only the fixed-K convention is shown, labelled as such.
- **No emergence claim.** Phases 1–3 show the frozen detector's own output over
  the prefix. The page does not say a thing "appears" at any particular step;
  it says what the detector proposed, and that its window is not filled before
  t = 8.
- **No re-derivation in JavaScript.** The client decodes stored heading strings
  and does set lookups (membership, entered/left, actuated, overlay hits). It
  never advances any dynamics.
- **No restyling of anything else.** The only shared code touched is
  `iiStopDynPlayback` (clears the new timer) and the `.iiDynViews` row (one new
  button). The new CSS uses new class names (`.iiPhaseStrip`, `.iiPhaseChip`,
  `.iiPhaseNote`, `svg.iiLattice.d10Lattice`) that no existing view references.

## 5. One sizing decision

The 6.10 header carries two rows the other views do not — the seven-beat strip
and the scope caption. At the narrowest audited viewport (1100×720) the shared
`svg.iiLattice { min-height: 320px }` floor would then push the playback
controls past the Details bar. A single scoped rule,
`svg.iiLattice.d10Lattice { min-height: 250px }`, lets the lattice shrink
instead. At 1280×800 and 1440×900 the lattice is far above either floor, so
nothing changes there, and no other view is affected. Measured graph-column
overflow past `.iiMain`: 6.10 is **0 px** at all three viewports (the existing
6.8 control view is 24 px at 1100×720; that was left alone).
