# MATHEMATICAL_CHECKS.md

Works every tiny example `IDENTITY_MODEL.md` commits to handling, plus the
counterexample/normalization/duplicate-invariance checks the mandate
requires before any large implementation proceeds. Each case is a minimal
synthetic scene — small enough to enumerate the global hypothesis space
exactly (§5's "exact reference for small scenes"). Where a case is
genuinely ambiguous, that is stated as the result, not resolved by fiat.

Notation: bird set at time `t` is a small labeled point set on a torus (or,
for the abstract cases, an unwrapped plane — torus wraparound is only
load-bearing in case 9). `f_ell`, `f_0` as in `IDENTITY_MODEL.md` §4 (the wrapped-elliptical mixture).
`RETENTION_MIN`, `GROWTH_RETENTION_MIN` etc. are NOT reused from
`lineage_611.py` — this document defines its own illustrative constants
(`r_min=0.3` retention floor, `tau_react=3` reachable-set sigma) purely to
make the worked examples concrete; the actual calibrated values are a Phase 2
deliverable (`VALIDATION_PROTOCOL.md`), not asserted here.

## Case 1 — Two independent tracks

**Setup.** Label A: 20 birds near `(2,2)`, heading North, `v_A ≈ (0, 0.28)`.
Label B: 15 birds near `(20,20)`, heading East, `v_B ≈ (0.28, 0)`, on a
`L=24` torus (so A and B are >8 units apart, well outside either's `S`).

**Model application.** Two components in the mixture, `pi_A`, `pi_B`,
`pi_0` for the remaining 365 unassigned birds. Since the components are
spatially disjoint (no bird's likelihood is ambiguous between `f_A` and
`f_B`), the per-bird assignment posterior is a hard 0/1 for every bird in
practice (soft only in principle) and `w_i^A`, `w_i^B` partition cleanly.
Global hypothesis enumeration: {continue A, continue B}, {continue A, death
of B + birth of new label}, etc. — all hypotheses other than "both
continue" require an unmotivated death+birth with zero supporting evidence
(no missing-candidate signal, no reachable-set violation), so they receive
negligible posterior mass under any reasonable death-prior. **Identifiable.**
Both labels persist with `e≈1`, non-overlapping membership, independent
trajectories in `G_t` (no edges between them).

**Check — normalization.** `pi_0 + pi_A + pi_B = 1` by construction; verified
trivially since `pi_A = e_A m_A/N`, `pi_B = e_B m_B/N`, remainder to `pi_0`.

## Case 2 — Duplicated proposal

**Setup.** Same as Case 1's label A (20 birds near `(2,2)`). Both the
Louvain proposal mechanism and the field-based proposal mechanism return the
IDENTICAL bird set `{1..20}` for this candidate at time `t` (a plausible
outcome for a well-separated, unambiguous clump — both detectors should
agree here).

**Failure mode being checked against.** A naive implementation that treats
each proposal mechanism's output as an independent "vote" would either (a)
multiply two identical likelihood evaluations of the same data (double-
counting), or, as in `lineage_611.py`'s actual behavior, (b) spawn two
separate `Hypothesis` objects (two `hid`s) for the same member set, each
carrying its own probability share, inflating the reported number of live
hypotheses and destabilizing any later MAP/argmax read (`CLAIMS_LEDGER.md`
item A2).

**Required behavior (per `IDENTITY_MODEL.md` §5's duplicate-coalescing-before-normalization step).** Candidate sets are
deduplicated by member-set identity BEFORE they enter the likelihood
evaluation or the hypothesis enumeration: `{proposal from Louvain, proposal
from field detector}` with identical `members` collapses to ONE candidate
with a provenance tag `{sources: [louvain, field]}` (used only to report
cross-mechanism agreement as evidence strength, never to double-count).

**Check — duplicate invariance.** Let `p*` be the posterior computed from
the deduplicated candidate list, and `p**` from a list where the same
candidate appears `k` times (any `k ≥ 1`). Requirement: `p** = p*` for every
`k`. This is a hard architectural check (not a numerical tolerance) —
verified by unit test asserting bit-identical output for `k=1,2,3,5`.

## Case 3 — Ambiguous crossing (ordinary case)

**Setup.** Label A (18 birds, heading East, center at `(5,10)`, `v_A=(0.28,0)`)
and label B (16 birds, heading North, center at `(9,10)`, `v_B=(0,0.28)`) are
approaching each other; at time `t*` their spatial extents `S_A`, `S_B`
overlap by roughly 40%, and roughly 6 birds fall in the geometric overlap
region.

**Model application.** Per-hypothesis, each bird in the overlap is assigned
to exactly one of `f_A`, `f_B` (§6 relation 2 — the Phase-1 primary model
does not permit one bird to be generated by both components within one
hypothesis). Because heading is part of each component's likelihood
(`Categorical(z; pi_A)` vs `Categorical(z; pi_B)`, and A/B have different,
well-separated heading distributions here), a bird observed heading East in
the overlap region is overwhelmingly assigned to A even though it is
spatially closer to B's center in some sub-cases — heading breaks the
spatial tie. Enumerating hypotheses over the 6 overlap birds' assignments
(2^6 = 64 combinatorial hypotheses, small enough to enumerate exactly)
collapses to a strongly peaked posterior (the heading likelihood ratio
dominates) rather than a uniform one. **Identifiable in this instance**,
BECAUSE the two objects differ in heading — this is disclosed as
instance-specific, not a general guarantee (see Case 3b).

**Case 3b — the harder version, same positions, indistinguishable
headings/phenotype.** If A and B instead have the SAME heading distribution
and the same phenotype `phi` (e.g. both moving East, both compact
same-size clumps, only their positions ever separated them), the 64
combinatorial assignment hypotheses for the 6 overlap birds are now governed
only by position likelihood — the position density gradient near the
overlap midpoint is shallow, so the posterior stays genuinely spread over
many assignment hypotheses. **Reported as elevated per-bird assignment
uncertainty** (`w_i^A`, `w_i^B` both well below 1 for the overlap birds,
summing to ≈1 across A+B — not to be confused with case-4 "shared
membership," §6 relation 3, which is a different, not-invoked-here model
choice), NOT resolved to a confident pick. Both labels' trajectories continue
uninterrupted through the crossing (`G_t` gets no split/merge edge — this is
relation 2 of §6, "overlapping regions," explicitly not an event).

**Important correction (caught by adversarial review of an earlier draft):
this ambiguity is a consequence of the §4 mixture's OWN chosen
simplification, not a fundamental data limit, and must not be described
with Case 10's stronger language.** `Y_t` retains a persistent per-bird
index — individual bird trajectories are NOT lost in the raw data. §4's
likelihood is deliberately i.i.d. per bird given only each label's
*aggregate* parameters `(c,\Sigma,\pi)` (this is what makes Case 7's full
material-turnover example work correctly), so it discards each of the 6
overlap birds' own recent individual heading/velocity history when
resolving this step's assignment — even though, in this constructed
scenario, that history could well be informative (e.g. a bird's own
heading over the last few steps, or which side of the crossing it
approached from, may already disambiguate it). A model extension using
short per-bird history (not just the current instant) as an additional
association feature could reduce or resolve this specific case; this
document does not build that extension, and reports the elevated
uncertainty above as the PRIMARY MODEL's honest output, not as a claim
that no information exists anywhere in the data. Reserve "the data does
not contain the resolving information" (§9's stronger claim) for Case 10
only, where individual-bird symmetry is stipulated all the way down, not
merely aggregate-parameter symmetry.

## Case 4 — Apparent detector merge vs. real merger

**Setup A (detector artifact).** Labels A (12 birds) and B (11 birds), truly
still distinct (different bulk velocities, `|v_A - v_B| = 0.3`, well above
noise), pass close enough that the Louvain candidate-detection graph
connects all 23 birds into one component at its declared affinity cutoff —
ONE candidate region is proposed at time `t`.

**Required model behavior.** Per §7's "temporary overlap / detector
merger" row: the single merged candidate region is evaluated against BOTH
`f_A` (assuming A continues, explaining ~12 of the 23 birds well and the
rest poorly) and a two-component explanation `f_A · f_B` (explaining all 23
well). If the two-component explanation's likelihood exceeds the
one-continues-one-unexplained explanation by more than the model-complexity
penalty implied by the prior over label count (a standard mixture-order
comparison — more components always fit at least as well, so the comparison
must penalize the extra label, e.g. via the label-birth prior mass, not a
raw likelihood ratio), the two-label explanation wins and BOTH labels'
trajectories continue with no split/merge edge, exactly as in Case 3.
**No merger is charged**, because a strictly-better two-label fit for a
single detected region is the definition of a detector artifact.

**Setup B (real merger).** Labels A and B converge and their bulk velocities
CONVERGE too (`v_A(t) → v_B(t)` over several steps, both bird populations
interleave and adopt one shared heading distribution, and one-hypothesis
`f_{A∪B}` explains the combined region distinctly better than any two-
component split once the two-component split's own component velocities
would have to diverge from what's actually observed). Per §7's "actual
merger" row: parent trajectories A and B both end at `t`, one new child
label `C` begins with parent edges to both A and B in `G_t`.

**The discriminating test, stated precisely.** It is NOT "one candidate
region vs. two" (that is a candidate-layer fact, symmetric between both
setups). It is whether the two-parent-continuation explanation remains a
good fit to the CURRENT frame's data. Setup A: yes (two distinguishable
sub-populations by heading/velocity still exist inside the one region) → no
event. Setup B: no (the data no longer supports two distinguishable
sub-populations) → merger event. This is exactly the discriminator
`IDENTITY_MODEL.md` §7 specifies and is the direct fix for "two detector
components automatically implies a true split" and its mirror error.

## Case 5 — Balanced split (genuine)

**Setup.** Label A, 30 birds, splits into two groups of 15 each at time `t*`,
moving apart with diverging bulk velocities that continue to diverge over
the following several steps (not a one-step fluctuation).

**Model application.** At `t*`, the candidate layer proposes 2 regions. The
continuation test (as in Case 4) is run: does ONE label A, continued, fit
the two regions' combined data better than two new labels? Because the
velocities are genuinely diverging and continue to diverge (checked over a
short window, not a single frame, to avoid charging a split for a one-step
detector fluctuation), the one-label continuation fit degrades over the
window while the two-label fit does not. **Split event**: A's trajectory
ends at `t*`, children A1 (15 birds) and A2 (15 birds) begin, both with a
parent edge to A in `G_t`. Mass conservation check: `m_{A1} + m_{A2} ≈
m_A` at `t*` (allowing for the background component absorbing any birds
that fell into neither daughter region — reported explicitly, not hidden in
rounding).

**This is explicitly a symmetric case**, included specifically because
`IDENTITY_MODEL.md` §7 warns against "choosing the target-favorable child"
for a control task bound to A — if a control task were bound to A at `t*-1`,
BOTH A1 and A2 are equally valid children and the original-object
preservation claim ends unconditionally at this event, regardless of which
child a controller might prefer.

## Case 6 — Genuine expansion (growth, not split)

**Setup.** Label A, 15 birds, grows to 40 birds over 10 steps by recruiting
adjacent background birds that adopt A's heading distribution and remain
spatially contiguous with A's existing extent throughout (one connected
component at every intermediate step, exterior contrast `D` never collapses
toward the population-wide background level).

**Model application.** Per §7 row 1 ("Continuation," which subsumes
background recruitment as a growth sub-case, not a separate row — a
correction from an earlier draft that gave recruitment its own row): same
label continues, `m` increases, `\Sigma` grows, `c` and `v` continue along
the motion-model reachable set from step to step (no discontinuous jump).
No split is charged because there was never a second distinguishable
sub-population — the growth is monotonic single-component absorption. This
is the direct positive control for Case 5: same broad phenomenon (member
count changing a lot) with the opposite correct answer (continuation, not
event), discriminated by connectivity + non-bimodality, not by mass alone.

**Check — this is also the discriminator for "individuation loss"**
(§7 row 2, `lineage_611.py`'s own concept, retained as a labeled
sub-case): if growth instead coincides with exterior contrast `D`
collapsing toward the population-wide background level (the growing
region is blending into ambient flock structure rather than genuinely
recruiting), status is reported as `individuation_loss` — distinct from
both ordinary growth (row 1) and a split (row 5): the label's own
boundary is dissolving into background, not dividing into two new labels.
Per row 2's own effect column, sustained individuation loss for `>= K`
steps converts to termination (row 6), not an instantaneous death —
`IDENTITY_MODEL.md` §7 retains this three-way distinction (bounded growth
/ individuation loss / split) as three explicit, separately-numbered rows
now, closing the broken "next row" cross-reference an earlier draft had.

## Case 7 — Complete material turnover in a moving pattern

**Setup.** Label A, 20 birds, translates steadily at `v_A=(0.28,0)` for 60
steps. Over that window, EVERY original member eventually exits the trailing
edge of A's spatial extent and is replaced by a new member entering the
leading edge — by step 60, membership overlap with step-0 membership is
exactly 0 (`R_M(t=60) = 0`), while `c`, `v`, `S`, `pi`, `phi` are all
continuous throughout (this is precisely PLAN.md Section S's target
phenomenon: `R_M ↓` while functional identity `R_F` and `Q_clump` stay high).

**Model application.** At every intermediate step, the motion-model
reachable set (§8) is satisfied (small, continuous `c` displacement
consistent with `v`), `S` and `phi` evolve slowly (small process noise
relative to the calibrated tolerance), and the candidate layer proposes one
connected, non-fragmenting region at every step. **No event is ever
charged** — retention-based tests alone (`R_retain` against the ORIGIN set,
as in `lineage_611.py`'s `origin`-relative bookkeeping) would show
catastrophic decay to 0 and, under a retention-floor-only rule, would
incorrectly charge a death/rebirth somewhere in the window. The correct
behavior requires the continuation test to be evaluated STEP-TO-STEP against
the immediately preceding state (not against a fixed origin), which is
exactly why `IDENTITY_MODEL.md` §3/§8 define `w_i^ell` and the reachable
set relative to the previous step's posterior, with origin-relative
retention reported only as a separate, explicitly-labeled diagnostic
(`R_retain_from_origin`), never as the continuation test itself.

**This is the single most important discriminating case in this document**:
it is the direct, worked demonstration that "identity via bird-ID overlap"
and "identity via label continuity" are different criteria that must give
different answers here, and that the model in `IDENTITY_MODEL.md` gives the
phenomenologically correct one (continuation) while a naive
retention-threshold rule gives the wrong one (spurious death).

## Case 8 — Destruction followed by a remote lookalike

**Setup.** Label A (18 birds, compact, heading North) dissolves at `t*` (its
members disperse into background — connectivity is lost, `D` collapses, no
successor candidate has `R_retain` above floor against A's last state). At
`t*+5`, a NEW candidate B appears, 18 birds, compact, heading North,
phenotype `phi_B ≈ phi_A`, but centered 15 units away — outside A's
motion-model reachable set even at `t*+5` (a reachable set built from A's
own last observed `v_A`, which was near-zero at dissolution, cannot stretch
15 units in 5 steps at any reasonable calibrated process-noise tail).

**Model application, per §7's redesigned rows 6–7 (an earlier draft had a
separate "destruction + distant lookalike" mechanism; this is now an
instance of ordinary termination followed by an ordinary, annotated
birth — see §7's revision note).** No candidate is ever in A's reachable
set after `t*` (its own last `v_A` was near-zero, so the reachable set
stays small); once elapsed time exceeds `\tau_{\text{missing,max}}`, row 6
fires TERMINATION on transport grounds alone — phenotype/shape is never
consulted for this call. B, appearing at `t*+5`, is not in ANY existing
label's reachable set, so row 7 fires: a BIRTH, no parent edge. Because a
label (A) was terminated within the lookback window and `\phi_B \approx
\phi_A`, B's birth record carries a `possible_lookalike_of=A` annotation
— purely descriptive, never a parent edge, never merging A and B's
probabilities. This is the direct worked counter-example to "translated
phenotype similarity is sufficient for continuation": similarity only
ever produces an annotation on an already-decided birth, never a vote in
the termination decision itself.

**Contrast case (should NOT terminate A at all).** If B instead
appeared at `t*+2`, 3 units from A's last position, consistent with A's
last observed (nonzero) `v_A`'s reachable set at the calibrated confidence
level — row 6's "no candidate in reach" precondition is FALSE (B IS in
reach), so this is ordinary continuation after a miss, not termination:
A's own trajectory is predicted forward through the 2-step gap and B is
its continuation, reported with elevated position uncertainty for the gap,
never as two events. The discriminating fact between this and the main
case above is entirely positional (in-reach vs. not), never phenotype
similarity — both cases have `\phi_B \approx \phi_A` by construction, and
that similarity plays no role in which one fires.

## Case 9 — Torus seam crossing (housekeeping check, not a new event type)

**Setup.** Label A crosses the periodic boundary (`x=0`/`x=L` seam) while
translating.

**Required check.** Every distance/displacement computation in §3/§4/§8
(`c` update, `S`, reachable-set evaluation, `local_exterior_contrast`) uses
the torus minimum-image convention consistently. A naive Euclidean
computation that does not wrap would report a spurious huge jump in `c` at
the seam and could incorrectly charge a death+birth purely from the
coordinate discontinuity. This is a code-correctness check, not an
identifiability question — included here because `lineage_611.py`'s own
`torus_delta` utility exists for exactly this reason, and any replacement
implementation must be checked against it on this exact scenario before
being trusted.

## Case 10 — Exactly ambiguous encounter (irreducible)

**Setup.** Two labels, A and B, IDENTICAL not merely in aggregate
parameters but at the INDIVIDUAL-BIRD level: every bird in A has a mirror
counterpart in B with the same relative position, same heading, and the
same recent (multi-step) individual heading/velocity history, related by
an exact reflection symmetry of the full scene (not just `S`, `m`, `pi`,
`phi` matching — this is the strengthened setup, distinguishing this case
from Case 3b, §Case 3b's correction above: here there is no per-bird
history left to exploit either, by construction). They approach on
head-on trajectories, occupy literally the same region for one step
(perfect spatial coincidence), then separate, preserving the reflection
symmetry throughout. There is no information in `Y_t`, at any level of
granularity down to individual bird trajectories, at the coincidence step
or after, that could, even in principle, tell you which departing group is
"A" and which is "B" — this is the true theoretical limit Case 3b only
approximates (Case 3b's ambiguity comes from the §4 model's choice to
discard per-bird history, which is in principle recoverable information;
Case 10's does not, because the setup removes that information from the
data itself, not merely from one model's likelihood).

**Required output.** A calibrated 50/50 (or, for `k`-fold symmetry, `1/k`)
posterior over the two (or `k`) possible label-continuation assignments,
reported explicitly as such. **This is not a defect to fix** — per
`IDENTITY_MODEL.md` §9, no observation model recovers information the data
does not contain. Any identity-sensitive control task bound to one of these
labels must invoke the declared wait/release/abstain policy (§4) at this
point rather than act on an arbitrarily broken symmetry. The failure mode
being checked against is a system that silently picks one assignment (e.g.
by array index or object-creation order) and reports it with false
confidence — this must not happen, and is checked by verifying the reported
existence/association probabilities are actually ≈1/k, not by checking
which specific label ends up on which side (that is, correctly,
unanswerable).

## Cross-cutting checks (apply to every case above)

1. **Normalization.** In every case, `pi_0 + sum_ell pi_ell = 1` and, within
   the global hypothesis enumeration, hypothesis posterior weights sum to 1
   (or, for the real 400-bird scale, sum to `1 - unaccounted_mass` with
   `unaccounted_mass` explicitly reported, per §5's truncation discipline).
2. **Duplicate invariance.** Re-run every case above with each candidate
   region additionally proposed by a second, dummy detector returning the
   identical member set; the posterior must not change (Case 2's check,
   applied everywhere).
3. **Event consistency.** No split/merge/death/birth edge is ever written to
   `G_t` without a corresponding transition-kernel term in §5/§7 that
   licenses it; conversely, an event that IS licensed by the data (Cases 5,
   8) is never suppressed to keep a track looking smooth (the mandate's
   explicit prohibition on cosmetic smoothing).
4. **Order/labeling invariance.** Relabeling which physical candidate is
   "region 1" vs. "region 2" in the input (arbitrary array order) must not
   change which label gets which output identity beyond the labels
   themselves being arbitrary — i.e., the ASSIGNMENT of physical birds to
   persistent labels must be invariant to input ordering, only the (also
   arbitrary) label IDs may differ.

## Which cases are identifiable and which are not (summary table)

| case | identifiable from data alone? |
|---|---|
| 1. two independent tracks | yes |
| 2. duplicated proposal | yes (invariance is the point) |
| 3. ordinary crossing (differing heading/phenotype) | yes |
| 3b. crossing, identical aggregate heading/phenotype | **not by the primary (aggregate-parameter) model — reported as elevated uncertainty; NOT claimed irreducible in principle, since per-bird history is in principle informative and simply unused here (see Case 3b's correction)** |
| 4. detector merge (still 2 objects) | yes |
| 4. real merger | yes |
| 5. balanced split | yes |
| 6. genuine expansion | yes |
| 7. complete material turnover | yes (continuation), but NOT via origin-relative retention alone |
| 8. destruction + distant lookalike | yes (correctly reported as death+birth) |
| 8-contrast. missed observation, reachable gap | yes (correctly reported as continuation) |
| 9. torus seam crossing | yes (housekeeping only) |
| 10. exactly ambiguous encounter | **no — irreducibly ambiguous, calibrated multi-hypothesis output is the correct and only correct output** |

Two cases (3b, 10) are stated in advance as not fully resolved by this
model — but for different reasons, kept distinct per the correction above:
3b is a MODELING CHOICE (the §4 aggregate-parameter mixture discards
per-bird history that could in principle disambiguate it) while 10 is a
genuine DATA limit (the setup removes distinguishing information from the
scene itself, not just from one model's likelihood). This is disclosed
here, before any implementation, per the mandate's requirement
that the analytical note state which cases are identifiable and which are
not — it is not a discovery to be made defensively after a validation
failure.
