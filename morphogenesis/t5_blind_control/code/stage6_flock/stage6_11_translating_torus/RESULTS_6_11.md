## 4. Relational passive predictor and predictive interface (items 6–7)

`predictive_boundary_611.py` / `run_predictive_boundary_611.py`. Score
`s_h(i,t) = b_h + Σ_j φ_h(z_j, dist_bin(i,j), bearing_octant(i,j))`, one
multinomial-logistic model per current-heading stratum (so `a_h(z_i)` is
absorbed as each stratum's own intercept), fit over a 96-dim category
histogram (4 headings × 3 equal-frequency distance bins × 8 bearing octants
— coarse, predeclared, **never using the true interaction radius**: bins are
quantile cut points of the training split's own pooled nearest-M_obs
distances). Permutation/translation invariant by construction: coefficients
are shared across every bird and every neighbour.

| M_obs | train logloss | val logloss | test logloss | uniform baseline |
|---|---|---|---|---|
| 12 | 0.364 | 0.407 | 0.446 | 1.386 |
| 20 | 0.341 | 0.389 | 0.430 | 1.386 |

Both pool sizes beat the uniform baseline by >3×; M_obs=20 is modestly
better throughout (sensitivity check, item 6).

**Boundary construction** (greedy, conditional, stopping by predeclared
δ_tol/min_gain/K_max): for one detected candidate (size 75), reduces mean
held-out periphery log-loss from 0.400–0.438 (interior-only conditioning) to
0.363–0.399 (12 exterior sources added, hitting the K_max=12 cap at both
pool sizes — disclosed: the boundary may be larger than 12 at this
candidate, K_max was a computational bound, never used as a target).
Full-pool oracle: 0.226–0.236 nats — the greedy set recovers roughly a fifth
to a third of the achievable gap.

**Certification** (single-challenger, bootstrapped over test episodes,
disclosed simplification of Stage 6.8's 3-challenger battery): **M_obs=20
certifies as predictively sufficient** (bootstrap upper bound 0.0043 ≤
δ=0.01); M_obs=12 does not at the same (reduced, memory-bounded) data volume
(upper bound 0.0392). An earlier run of M_obs=12 with more construction/test
rows (6,000 vs 3,000 construction rows, unrestricted vs 400/episode test
rows) *did* certify (upper bound 0.0045) — illustrating that this
certification is a genuine statistical test whose power depends on held-out
data volume, not a fixed property of the boundary. See Fig 6.11-3 (left).

## 5. Causal interface (item 11) — and a bug this stage caught

**Critical correctness fix, disclosed explicitly.** The first implementation
of `do(Z_j=z')` intervened on the exterior source's *drawn action* (via
`forced_actions`). This is provably a no-op on every other bird's next state
in this update ordering: `G_i(t)` for bird i is fixed from `z(t)` before any
action is drawn, so forcing j's action can only change j's own outcome, not
i's. The correct intervention — matching Stage 6.8/6.9's own `probe(Z_j=z')`
design and task brief item 11's formula — sets bird j's *current* heading
`z_t[j] := z'` before that step's `G` computation, so it changes what j's
*neighbours* observe. Verified directly: the fixed probe gives 0.45
discrepancy on a true live neighbour and exactly 0.0 on a distant
unconnected bird; the closed-form exact effect (§7) agrees. This is recorded
here rather than silently fixed because it is exactly the kind of mistake
the reachable-horizon discipline in item 13 is designed to make legible —
one-step **task-neutral** effects on OTHERS require a state intervention,
one-step **action-forcing** never propagates past the actuator itself.

**Budget sensitivity** (`run_causal_budget_sensitivity_611.py`, primary
regime, one candidate with a 28-bird exterior pool within 1.5R):

| rollouts × repeats | \|B_causal\| | mean bootstrap CI width |
|---|---|---|
| 20 × 3 | 1 | 0.0094 |
| 40 × 3 (Stage 6.10 reference) | 2 | 0.0075 |
| 80 × 3 | 7 | 0.0053 |

Monotonic: more rollouts recover more of the true causal set (bird 328
detected at every budget; 197 from 40 rollouts; 5 more join at 80) and
tighten the CI, exactly the expected finite-sample behaviour. Method:
nonparametric bootstrap over pooled rollouts ("finite-sample interventional
estimation" per item 11's explicit fallback wording — the full per-bird
4-category Dirichlet treatment was judged to add complexity without changing
the B_causal decision rule, which only needs a lower confidence bound).

## 6. Oracle reveal (item 18) — run last, feeds back nowhere

`oracle_611.py` / `run_oracle_reveal_611.py`, same snapshot as §§4–5. Exact
effect computed in closed form (`u_i @ Bu.T`, zero sampling error) rather
than by rollouts, isolating estimation error from identifiability:

| comparison | precision | recall | Jaccard |
|---|---|---|---|
| B_pred (M_obs=20, item 6–7) vs B_D (true) | 0.083 | 0.056 | 0.034 |
| B_causal, sampled (40×3) vs B_D (true) | 1.000 | 0.111 | 0.111 |
| **B_causal, exact vs B_D (true)** | — | — | **1.000** |
| B_causal, sampled vs exact | — | — | 0.111 |

**The exact causal interface is IDENTICAL to the true live-neighbour graph**
(Jaccard=1.0) — do(Z_j=z') one-step interventions are, in the infinite-
rollout limit, exactly identifiability-equivalent to the physics' own
directed edge set. The finite-sample (40×3) estimate recovers only 2 of the
true 18 sources at this snapshot (Jaccard 0.111 against both the true graph
and the exact effect) — consistent with the sensitivity table above, and
squarely an estimation-error story, not an identifiability one: more budget
recovers more of the set (§5).

**B_pred is only weakly related to B_D** (Jaccard 0.034) — the predictively
useful sources are largely *not* the true one-step causal parents. This is
the expected, and scientifically the more interesting, outcome: predictive
sufficiency and causal structure are genuinely different objects (item 7's
own warning), and this stage's B^pred/B^causal/B^C separation (item 12) is
what makes the difference visible rather than papered over.

`B_C` vs `B_D` is not evaluated at this static snapshot (B^C requires a live
episode with an active target; see §7's online runs for B^C's own
composition) — a disclosed scope limitation, not a null result.

## 7. Online loop, translation task, control, and release (items 12–17)

`run_online_control_611.py` implements the full loop
`Y_{0:t} → candidates → Î_t → B̂^pred_t → B̂^causal_t → Â_t → S_t → u_t → Y_{t+1}`,
with B^pred/B^causal/B^C computed by three **structurally distinct**
procedures (predictive-boundary greedy construction; one-step task-neutral
probing; τ=4 signed target-directed multi-step authority — never ranked by
one-step KL/discrepancy, per item 12's explicit prohibition). Re-detection
every step; re-inference on cadences (12/8/8 steps for pred/causal/authority)
with the stale estimate propagated and its age recorded in between. A
qualifying local collective (persistent ≥30 steps, moderate size, net
displacement ≥3R, tracked by the SAME blind lineage tracker used
throughout — never the privileged Section O diagnostic) triggers the
target: the adjacent 90° CCW cardinal direction of the lineage's own
*observed* bulk-translation vector. Actuators are drawn only from birds
**outside** the current interior.

Reduced compute budgets relative to the Stage 6.10 reference (K_act=8 not
10, T_control=T_release=24 not 40, probe rollouts 20×2 not 40×3, authority
rollouts 10 not 20) — a disclosed session-compute accommodation, not a
result of tuning against outcomes; see `run_causal_budget_sensitivity_611.py`
for the full-budget causal-interface check run separately at the reference
budget.

**5 online episodes, primary regime** (seeds 500–504):

| seed | control turned it? | control frac@target start→end | release frac@target mean/final | classification |
|---|---|---|---|---|
| 500 | no | 0.12 → 0.06 | 0.05 / 0.02 | actuation never turned it |
| 501 | yes | 0.23 → 0.76 | 0.86 / **1.00** | entered a new self-maintaining translating state |
| 502 | yes | 0.19 → 0.30 | 0.42 / 0.86 | entered a new self-maintaining translating state |
| 503 | yes | 0.05 → 0.72 | 0.79 / 0.89 | entered a new self-maintaining translating state |
| 504 | no | 0.11 → 0.03 | 0.04 / 0.04 | actuation never turned it |

**3 of 5 episodes turned the lineage and the turn persisted, unforced,
through the full release window** — in two of those (501, 503) alignment
with the target heading *continued rising after release*, and the interior
never dissolved in any of the 5 runs (`release_interior_dissolved=false`
throughout). This is a materially different outcome from Stages 6.8–6.10's
near-uniform controllability failures, plausibly because this regime's
smaller interior (~20–40 members, vs ~95–145+ in earlier stages) and
markedly lower policy saturation than Stage 6.9's failed spec give the
actuator boundary real authority. The other 2 episodes show a clean
**bimodal** failure mode — control never raised target alignment at all
(monotonic decline, not a rise-then-revert) — rather than a partial or
marginal outcome; no seed in this small sample landed in between. Given
n=5, this is a qualitative demonstration at the primary regime, not a
calibrated success-rate estimate (the discipline is honesty about that; see
Stage 6.10 Part H for what a proper controllability study covering budget
and horizon looks like, not repeated here).

## 9. Interpretation discipline (PLAN.md Section V, carried forward)

No method-success claim is made where a benchmark says the task is
uncontrollable — none is; this stage did not run a Stage-6.10-style
full-model controllability benchmark, so §7's positive result is reported as
"3/5 seeds at reduced budget," not "the task is controllable." The candidate
interior is never called ground truth (§6 shows its predictive/causal
composition differs substantially from B_D). Thingness thresholds and the
physical regime (§1) were never touched by control outcomes. The one
genuine bug this stage found and fixed (§5) is disclosed rather than quietly
patched, per the same discipline applied to every other stage's audit trail
in this codebase.
